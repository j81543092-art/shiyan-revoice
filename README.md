# 拾言 ReVoice

> 面向失语症患者的意图重建沟通助手 —— 把「AI 猜」变成「人确认」

---

## 这是什么

失语症最容易被误解的地方是：**患者听得懂一切、想得明白，只是说不出来**。
国内失语症人群约 **310 万 ~ 570 万**（卒中患者 1494 万 × 患病率 21%~38%）。

患者点几个图标、说一个词，系统给出 3~5 个候选意图并排序，**最终由患者本人点选确认**。
AI 不替他说话 —— 这是整个产品的立意。

三类现成方案都卡在不同地方：

| 方案 | 卡在哪 |
|---|---|
| 通用语音助手 | 假设用户能把话说清楚，而患者恰恰说不清楚 |
| 传统 AAC 图板 | 静态符号查找，不推断意图，认知负担全在患者身上 |
| 大模型聊天机器人 | 直接给断言式回答 —— 对患者就是「替他说话」，说错了他自己都没法纠正 |

**中间这道缝就是我们的位置**：从残缺的线索推到完整的意图，这一跳目前没有产品在做。

## 快速开始

```bash
cd app
node scripts/seed.js        # 灌入基础词表（首次运行）
node server/index.js        # 启动服务
```

| 页面 | 地址 | 说明 |
|---|---|---|
| 患者端 | http://localhost:3000/ | 三屏表达台，紧急按钮首屏常驻 |
| 家属端 | http://localhost:3000/caregiver.html | 实时表达 / 记录 / 词库 / 指标 |
| 登录 | http://localhost:3000/login.html | 邮箱账号（需开通云服务后端） |

**零外部依赖** —— 只用 Node 内置模块，无需 `npm install`。要求 Node ≥ 20。

### 答辩演示

```bash
bash demo.sh          # 10 步，每步对应一个可当场验证的机制点
bash demo.sh --keep   # 保留历史记录
```

## 产品机制规格 R1~R8

这是产品的**对外契约**，改动须走规格变更流程。

| 编号 | 规则 | 内容 |
|---|---|---|
| **R1** | 候选数量 | 默认 3 个；线索充分（≥3 类）可到 4~5 个；凑不出 2 个有区分度的候选时触发澄清，**不硬凑** |
| **R2** | 排序与锁定 | 按综合置信度降序；**排序后位置锁定** —— 同一会话内同一批线索，候选位置不得变动 |
| **R3** | 置信度呈现 | 患者端不显示百分比数字，用排序位置表达；**家属端可见数值** |
| **R4** | 澄清触发 | ① top1 < 0.6 → 是/不是；② 前两名差值 < 0.1 → 二选一；③ 最多 2 轮，不收敛则展示全部候选 + 「都不是，重来」 |
| **R5** | 确认 | 患者点选候选即确认；进入「已表达」状态并朗读，家属端实时同步 |
| **R6** | 紧急通道 | 疼痛/跌倒/呼救设首屏常驻一级大按钮，点击即通知家属端并留痕，**零模型调用** |
| **R7** | 个性化配置 | 家属/治疗师可增改词条；**紧急词不可删**；改动留痕可回滚；习得词须家属审核后生效 |
| **R8** | 输出措辞 | 第一人称口语短句（≤15 字）；禁用医学诊断措辞；禁止臆造线索中不存在的人名、药名 |

### 综合置信度公式

```
综合置信度 = 模型置信度 × 0.40 ＋ 场景先验 × 0.20 ＋ 线索覆盖度 × 0.25 ＋ 个性化加权 × 0.15
```

**不用模型裸分数排序** —— 裸分数不可校准，同样的线索换个问法分数就变。
场景先验与个性化加权是「懂这个患者」的证据：同一个「水」字，对一个患者是喝水、对另一个可能是吃药送服。

## 三条产品红线

### 红线一 · 紧急表达一键通道，不走 AI

疼痛、跌倒、呼救等紧急表达：首屏常驻大按钮，不藏在任何层级里；点下直达家属端通知流程，**零模型参与**。

| 规则 | 触发条件 |
|---|---|
| R6-① | 一级紧急词直接命中（跌倒了 / 喘不上气 / 救命…） |
| R6-② | 连点同一症状词 ×3 + 身体部位 |
| R6-③ | 二级紧急词 + 任一其他线索 |

> **命悬一线的事，不允许任何「AI 猜一下」。**

### 红线二 · 交互为人群身体条件让路

大图标、高对比、少层级、防误触。
WCAG 2.2 触控目标下限是 ≥24px，**我们按 84px 做**（患者手会抖）。

### 红线三 · 个性化有边界

紧急词不可删；习得词须家属审核后才生效；一切改动留痕可回滚。

## 测试与评测的分工

两者互补，缺一不可：

| 命令 | 作用 | 数量 |
|---|---|---|
| `node eval/test-contracts.js` | **守底线** —— 有没有越界（R1~R8 红线） | 40 条 |
| `node eval/run-eval.js` | **爬上限** —— 答得准不准 | 20 条 |

评测集关注准确率，契约测试关注机制契约。**一个真实的教训**：曾有一版 `clarify.js`
用 `answer.includes('是')` 判定肯定，导致患者答「不是」反被系统确认成「是」——
跑分器全绿（它只判候选有没有命中标准答案），但产品在最核心的确认环节替患者撒了谎。
正因为这个缺陷，才有了 `test-contracts.js`。

### 基线指标（规则引擎 · 评测集 v1）

```
Top-3 命中率     42.9%（6/14 常规）
平均澄清轮次     0.60
澄清判定正确率   50.0%
紧急通道正确率   100%（零模型调用）
整体通过率       50.0%
```

> **数字的起点低不丢人，没有曲线才丢人。**
> 已写入 `prompt_versions` 表（版本号 `v1-rule`），接华为云大模型后每版追加一行。

## 模型接入

适配层已就绪，**三种 provider 同一契约**，切换只改环境变量：

```bash
# 华为云 MaaS / ModelArts Studio（答辩正式环境）
# 认证是 Bearer API Key，不是 AK/SK 签名
MODEL_PROVIDER=huawei HW_MAAS_API_KEY=... \
HW_MODEL_ENDPOINT=https://api.modelarts-maas.com/v2/chat/completions \
HW_MODEL=DeepSeek-V3

# 任意 OpenAI 兼容接口（联调过渡）
MODEL_PROVIDER=openai LLM_API_KEY=... LLM_BASE_URL=... LLM_MODEL=...

# 规则引擎（默认，零凭证，全链路照常可跑）
node server/index.js
```

未配置凭证时自动降级到规则引擎 —— **演示不中断**，评测数字照常产出。

### ⚠️ AK/SK 与推理接口无关（容易搞错）

华为云有两套认证：**模型推理**用 `Authorization: Bearer {API_KEY}`；
**管控面**（开通服务、查配额）才用 AK/SK + SDK-HMAC-SHA256 签名。
本项目只调推理接口，所以必须去 MaaS 控制台创建 **API Key**，光有 AK/SK 调不通。

完整取数步骤见 `app/README.md`「华为云接入取数步骤」。

> 赛题规定 AI 能力由华为云提供，因此不做 fine-tuning / RAG / Agent 框架。
> 战场在提示词与评测，不在模型内部。

## 部署

```bash
docker build -t shiyan-revoice:0.1.0 .
docker run -p 8080:8080 -e PORT=8080 shiyan-revoice:0.1.0
```

服务监听 `PORT` 环境变量并绑定 `0.0.0.0`，适用于任意容器平台（Render / Railway / Fly.io / 华为云等）。

生产环境替换清单（本地实现与云端键语义已对齐，上层代码不动）：

| 本地实现 | 云端 | 替换位置 |
|---|---|---|
| `node:sqlite` | RDS | `server/data/db.js` |
| 进程内 LRU 缓存 | Redis | `ClueCandidateCache` |
| 规则引擎 | 华为云大模型 API | `server/model/providers/huawei.js` |

### 账号登录（可选）

`public/login.html` 已接入 WorkBuddy 云服务的邮箱认证（密码登录 / 验证码登录 / 注册 / 忘记密码）。
需要开通云服务后端并把 `publicConfig` 填入 `app/public/js/cloud-config.js`。
未开通时登录页会**明确提示**云服务未就绪，不会给出假登录。

> Web 应用仅支持**邮箱**登录。手机短信与微信登录仅在微信小程序可用 —— 这是平台能力边界，不是实现遗漏。
